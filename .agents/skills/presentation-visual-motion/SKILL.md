# Presentation visual design and motion

## Trigger

Use after the presentation’s audience, evidence, and slide purpose are known, when a defence deck needs a coherent visual language and purposeful animation.

## Inputs

- Slide outline, audience, delivery setting, and required format
- Approved evidence, brand constraints, and any existing deck to preserve
- Whether native PowerPoint animation, a motion asset, or a written motion plan is required

## Procedure

1. Start from `templates/presentation-design-motion-brief.md`; record aspect ratio, viewing conditions, font availability, and the one message per slide.
2. Apply the token system in `references/dala-style-tokens.md`: black canvas, white type, restrained violet action/accent, amber emphasis, and generous negative space.
3. Adapt web-scale typography for slide readability. Use PPNeueMontreal only when it is available and licensed for the deck; otherwise use Inter. Keep the hierarchy and spacing, not an inaccessible pixel-for-point conversion.
4. Choose a flat composition for each slide: cover, section break, key claim, evidence comparison, editable chart/table, process, or closing. Avoid dashboard grids, shadows, decorative borders, and repeated cards.
5. Write a motion plan that reveals information in reading order. Use one restrained animation vocabulary per section: usually fade or appear, 0.25–0.5 seconds, no automatic looping, and no exit effect unless it clarifies a comparison.
6. Use a generated or licensed abstract visual only when it helps the narrative. Do not copy the source site’s logo, particle constellation, screenshots, or distinctive layout as a deck asset.
7. Render or present a draft at realistic viewing size. Check contrast, text fit, slide pacing, source visibility, and whether every animation clarifies a relationship or can be removed.

## Motion boundaries

- A motion plan is not proof that a PPTX contains working animations. If the authoring tool cannot preserve native motion, deliver the plan and state that limitation.
- Never animate evidence in a way that changes its meaning, hides a caveat, or implies a sequence unsupported by the source.
- Avoid typewriter, bounce, spin, zoom, auto-advance, and decorative looping effects in a defence deck.
- Respect reduced-motion requests and provide a static reading order where animation is absent.

## Done

Each slide has a purpose, composition, token choices, editable evidence treatment, and a motion instruction with trigger and duration. The draft is readable at the delivery scale and the style reference is identifiable only as inspiration.

## Ownership and revision

The presentation owner approves the visual direction and motion intensity before export. Revise when the rubric, venue, brand constraints, or source evidence changes.

## Reference routing

Read `references/dala-style-tokens.md` for the approved token application. The style reference is a visual direction, not a template or asset library.
