# Запуск агента Project Harness

`AGENTS.md` — рабочая инструкция для Codex. Этот файл — короткий сценарий запуска для владельца; он не заменяет `AGENTS.md`.

## Один раз в Codex Desktop (Windows)

1. Откройте или добавьте локальный проект с основной папкой:

   ```text
   C:\Users\Екатерина Поварнина\Desktop\агент-обвязка проекта\project-harness
   ```

2. Выберите эту папку как **основную** для проекта. Не используйте её родительскую папку как основную: тогда Codex может не обнаружить `AGENTS.md` автоматически.
3. Внутри проекта создайте новый чат в режиме **Codex → Local**. Для обычной работы обвязки worktree не нужен.
4. Отправьте первое сообщение:

   ```text
   Оркестратор: начни сессию. Проверь актуальное состояние и предложи ближайшее действие без внешних изменений.
   ```

Codex прочитает `AGENTS.md` из основной папки. Вставлять его содержание в чат не нужно.

## Для новой сессии

Создавайте отдельный чат для отдельного результата, но всегда внутри этого же локального проекта. Для продолжения текущей работы используйте существующий чат.

Минимальное сообщение для старта:

```text
Статус
```

## Команды переключения

| Сообщение | Результат |
|---|---|
| `PM: <цель>` | План, статусы, риски и план/факт через YouGile. |
| `2.5: <цель>` | Разработка, исправление, рефакторинг, тест или UI-проверка CoreTeams Product Web. Исследование и спецификация — только по явному запросу или при блокере веб-правки. |
| `2.5 React: <цель>` | Согласованная миграция статического веба в React. |
| `Видео: <цель>` | Сценарий, промты и план сборки ролика CTF. |
| `Презентации: <цель>` | Структура, тексты, доказательства и подготовка защиты. |
| `Пилоты: <цель>` | Исследование, интервью, синтез результатов или план пилота. |
| `Пилоты: гипотеза спринта <гипотеза>` | Проверка продуктовой гипотезы с пользователями в текущем спринте. |
| `Оркестратор: <цель>` | Вопрос сразу по нескольким направлениям. |
| `Неделя` | План недели. |
| `Статус` | Короткий статус пяти направлений и блокеры. |

## Границы действий

- Агент меняет файлы `project-harness` и после проверки синхронизирует их с GitHub.
- Он не пишет участникам, не рассылает приглашения, не публикует материалы и не меняет исходный проект без отдельного прямого разрешения.
- Для продуктового спринта начинайте с одной проверяемой на пользователях гипотезы. Если проверка не состоялась, агент фиксирует `NOT_RUN`, а не выдаёт предположение за результат.

## Опционально: запуск из терминала

Если Codex CLI установлен, запустите его из папки обвязки или укажите папку явно:

```powershell
codex --cd "C:\Users\Екатерина Поварнина\Desktop\агент-обвязка проекта\project-harness"
```

Дальше используйте те же команды переключения. Для Codex Desktop предпочтителен запуск локального чата в проекте: так файлы и `AGENTS.md` становятся контекстом сессии.
