## Отправленный комментарий — точная цитата

> Илья, по вопросам 16–21 от web-направления предлагаю следующее для совместного согласования.
> 16. Основной вариант — B.
> Берём web-product из PR #11: онбординг, контекст/файлы, вопросы, выбор AI-команды, план и рабочее пространство с версиями. A сохраняем как технический reference, но не требуем поддержки двух независимых API. Контракт B корректируем по общей сверке — он пока proposed.
> 17. Неизвестный исход и восстановление.
> В web добавляем отображение outcome_unknown и признаков прерывания/восстановления. Не показываем успех и не запускаем повтор автоматически. При этом обычный HTTP timeout не означает терминальный outcome_unknown на сервере: сначала перечитываем состояние. Техническое завершение Run отделяем от проверки результата пользователем.
> 18. Структурированные вопросы.
> Поддерживаем весь questions[]: варианты, множественный выбор и собственный ответ, когда он разрешён. Передаём ответы с точными ключами исходных вопросов; multi-select — по текущему протоколу runner. Ответ фасилитатору продолжает тот же Run. При unknown_fork загружаем актуальный вопрос, старый ответ автоматически не переносим.
> 19. Этапы, роли и файлы.
> План и выбранную AI-команду пользователь согласует в web. Gateway проверяет этапы по сохранённому плану, роли — по доступному реестру CTF. Файлы должны реально передаваться до запуска с проверкой bytes/hash. Название роли в prompt ещё не доказывает её исполнение: фактическую работу показываем по событиям.
> 20. Доработка — новый Run, но прежняя задача.
> После завершения Run доработка запускает новый Run внутри того же проекта, связанный с исходным документом и версией. Пользователь остаётся в том же рабочем пространстве, с контекстом и историей. Завершённый Run не переоткрываем; повтор доставки запроса не создаёт дублей. Это потребует изменений текущего B.
> 21. Сохранение и одобрение различаем.
> «Сохранено» — только после подтверждения хранилища для конкретной версии. «Одобрено» — отдельное подтверждённое сервером действие пользователя; оно не меняет содержимое версии.
> Событие artifact.approved нельзя просто дописать после терминального события Run. С Димой и Ариной нужно согласовать хранение одобрения на уровне документа/проекта либо другой совместимый механизм.
> Эти ответы — основа согласования, не заявление о готовой реализации.

## Область принятого решения

Это позиция владельца направления web, а не новая принятая всей командой версия событий/API. Базовый пользовательский вариант B сохранён; A reference.
