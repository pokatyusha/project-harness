## Обязательные тестовые сценарии (ещё не выполнены)

| Сценарий | Ожидаемое доказательство |
|---|---|
| Два artifact.created, второй ещё не сохранён | Нет run.completed; после обоих durable ACK — два сохранения и один последний terminal |
| Timeout storage → outcome_unknown → поздний commit | Один outcome_unknown, никаких новых событий/revision Run; операция сверена отдельно |
| Crash после push до confirm БД | Найден тот же Operation-Id/hash; ни второго commit/версии, ни вызова модели |
| Crash после confirm до доставки клиенту | Replay с теми же event_id/seq, без повторной версии и метрики |
| Повтор ключа с тем же/иным телом | Та же операция/receipt либо явный конфликт; не новая задача |
| Два вопроса, multi-select, restart | Точные text→answer; тот же Run; unknown_fork перечитывает вопрос без автопереноса |
| Доработка completed-результата | Новый Run/версия, прежний документ и immutable history сохранены |
| Approval сохранённой/несохранённой версии | Receipt только для сохранённой; повтор возвращает прежний; следующая версия не одобрена автоматически |
| Другая учётная запись или project/version mismatch | Отказ без утечки содержимого/метаданных; никаких мутаций |
| Download/ZIP/reopen после restart | Bytes/hash/состав совпадают с подтверждёнными версиями, не с живой ФС runner |

После контрактных тестов — реальный сквозной путь с вводными, выбором команды, уточнением, ответом, сохранением, скачиванием и восстановлением. DEPLOYMENT_READY, реальный сервер/CTF и baseline участника требуются отдельно перед пользовательским сравнением.

## Как зафиксировать вердикт

Для каждого спорного пункта: **принимаю / правка (раздел + текст) / не реализовано (что и где нужно)**. Указать commit и проверку, а не только «готово». Имена API, интерфейсы и коды ошибок закрепить в существующем источнике соответствующей границы. Сроки и merge owner этим пакетом не назначаются.
